PatrickOS Recovery privacy policy

Policy date: 5 October 2026.

PatrickOS Recovery is a personal desktop backup and restore tool operated by its owner. This policy describes its use of Google Drive data and the public information pages.

Google data accessed

The application requests https://www.googleapis.com/auth/drive.file. It accesses the contents and metadata of backup repository files and folders created by, or explicitly authorized for, the application. Metadata may include file identifiers, names, sizes and timestamps. It creates, reads, updates and deletes these files for backup operations, repository locking, verification, recovery and owner-authorized maintenance.

Purpose and use

Google Drive data is used only to provide personal backup and restore functions. It is not sold or used for advertising, unrelated profiling or AI model training. No advertising or analytics service receives backup data from this application.

Storage and security

Source history and explicitly selected project data are prepared locally and encrypted by Restic before upload. Encrypted repository files are stored in the owner's Google Drive account. Google can still receive storage metadata such as opaque repository file names, sizes and transfer times. Google handles account sign-in and the hosting of Drive files under its own service terms.

OAuth authorization credentials and recovery configuration are held in restricted storage on the owner's computer. The Restic password is protected locally and must also be retained independently by the owner. Recovery credentials are not committed to Git or included in the recovery pack they unlock.

Local staging packs and restored project data contain readable private material. They are stored in restricted local folders; access restrictions are not a substitute for device security or disk encryption. There is no central PatrickOS Recovery server receiving this data.

Sharing

The application transfers encrypted backup files to the owner's selected Google Drive account. It does not publish backup contents or share them with other users. The owner controls account access, any Drive sharing settings and any later disclosure of recovered data.

Retention and deletion

The owner selects backup retention and approves maintenance. Existing backups remain until the owner removes them or enables an authorized retention process. Deleting repository files can make recovery impossible. Google Drive's own deletion and retention behavior also applies.

The owner can revoke this application's access using Google Account connections. Revoking authorization stops future authorized access; it does not automatically delete existing backups. The owner can separately remove backup files in Drive and local staging or restored copies.

Public information pages

These pages do not set application cookies, load analytics or provide forms for collecting personal information. The website hosting provider may process standard connection and request metadata under its own privacy terms. Private source, project data, credentials and backup contents are not included in these pages.

Contact and changes

For questions about the application or its data practices, use the support email shown on its Google authorization screen. This page will be updated if the application's data practices change.
